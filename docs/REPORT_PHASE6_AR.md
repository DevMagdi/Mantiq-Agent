## 2. الافتراضات والانحرافات

1. **مفتاح المحاسبة على مستوى النشر، لا على مستوى المستأجر.** مفتاح المستأجر كان سيبقي الوحدة ظاهرة في الـ API وقائمة الصلاحيات والواجهة — وهو الأثر المطلوب إزالته.
2. **افتراضيات الصوت نزلت مع إيداع المحاسبة.** السؤال واحد (ما الذي يعرضه تثبيت تجريبي؟) والجدول واحد في `docs/ENVIRONMENT.md`؛ فصلهما كان سيترك التوثيق يصف حالة لم توجد.
3. **الويب هوك لا يُرجع 404 لرقم مجهول.** Meta تعيد المحاولة على 404 بلا نهاية؛ `200 {processed: 0}` مع حدث تدقيق هو الجواب الوحيد الذي يوقف الحلقة دون اختراع مستأجر.
4. **`uharfbuzz` بدل مكتبة إعادة تشكيل عربية.** هو المحرك الذي يستدعيه ReportLab أصلًا، ووافق المستخدم على إضافته قبل الإضافة (قاعدة 4).
5. **تعديل خطوتَي CI بعد فشل حقيقي.** الوظيفة على PostgreSQL فشلت لأن بذر البيانات صار لا يكتب دليل الحسابات عند إيقاف الوحدة، والاختبار الذي يلي يستخدم الحسابين `510100` و`210100`. أُضيف `ACCOUNTING_ENABLED=true` صراحةً لتلك الخطوتين؛ **لم يُخفَّف أي ثابت ولم يُحذف أي فحص**. أُعيد إنتاج الفشل محليًا أولًا (0 صف في `gl_account` عند الإيقاف، 22 عند التشغيل).
6. **سكربت الرحلات صار يبذر كلمة مرور خاصة به** بدل كلمة مرور العرض العامة، لأن النسختين تعملان بـ `APP_ENV=staging` والفحص الجديد يرفض الإقلاع بكلمة المرور المنشورة.
7. **لا شيء حُذف:** وحدة المحاسبة، جداولها، ترحيلاتها، واجهات الصوت، ومحوّلات المورّدين — كلها باقية خلف مفاتيح.

## 3. ما لم يُشغَّل هنا (بصراحة)

1. **صفحة PDF العربية لم تُعرض بكسليًا.** لا يوجد في البيئة أي مُرقِّم PDF (`pdftoppm`/`mutool`/`qpdf`) ولا محرك رسم لـ Pillow. الاختبارات تثبت: تضمين الخط، استخدام مشغّلات الرسم المشكَّلة، وترتيب المقاطع من اليمين إلى اليسار؛ والعينة للمراجعة البشرية في `/tmp/po_arabic_sample.pdf`. خطوات الفحص في `docs/RUNBOOK.md`.
2. **لا اتصال حقيقي بأي مورّد.** Meta وTwilio وSMTP جُرِّبت مقابل خوادم محلية تتكلم صيغ المستندات نفسها، وعلى نسختين حقيقيتين مع Redis حقيقي. أول اتصال حقيقي بكل مورّد يبقى «اختبار تكامل بعين بشرية».
3. **لا متصفح.** حزمة المتصفح في Playwright لا يمكن تنزيلها هنا، فمجموعة اختبارات المتصفح مفحوصة أنواعها فقط؛ الرحلات نفسها تعمل بلا متصفح في `scripts/e2e_journeys.py`.
4. **لا Docker ولا خادم PostgreSQL محليًا.** الترحيلات جرت على بديل SQLite؛ وظيفة PostgreSQL في CI هي الدليل على RLS و`pgvector` و`pg_trgm` (وقد نجحت).
5. **لا بيانات اعتماد حقيقية لأي مورّد.** لم يُستبدل شيء مزيف بدلًا منها.

## 4. خطوات التحقق اليدوي (Windows + PyCharm + uvicorn + ngrok)

**المتطلبات:** Python 3.11، Node 20، PostgreSQL 16، Redis (اختياري للتجربة)، حساب Meta للمطورين (مجاني).

1. **قاعدة البيانات والتشغيل (PyCharm):** افتح `backend` كمشروع، أنشئ `.env` من `deploy/.env.example` واضبط `DATABASE_URL` و`SECRET_KEY` (32 حرفًا فأكثر) و`ENCRYPTION_MASTER_KEY`، ثم من Terminal داخل PyCharm:
   ```powershell
   python -m venv .venv; .\.venv\Scripts\Activate.ps1
   pip install -e ".[dev]"
   alembic upgrade head
   python -m app.cli bootstrap --demo
   python -m app.cli seed-demo
   python -m app.cli doctor
   uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
   ```
   افتح `http://127.0.0.1:8000/api/docs` — **يجب ألا تجد أي مسار محاسبي** (سلوك مقصود). غيّر `ACCOUNTING_ENABLED=true` وأعد التشغيل لتظهر.
2. **الواجهة:** `cd frontend; npm ci; npm run dev` ثم سجّل الدخول `admin@pilot.procureai` / `Demo!Pilot2026` — مع `ACCOUNTING_ENABLED=false` لا توجد مجموعة محاسبة في القائمة ولا مسار `/accounting`.
3. **واتساب (ngrok):**
   ```powershell
   ngrok http 8000
   ```
   - في شاشة **الإعدادات → التكاملات → واتساب**: المزوّد *Meta Cloud API*، **Phone Number ID**، التوكن، **App Secret**، **Verify Token**. اضغط **اختبار الاتصال** — أخضر `Live` يعني وصولًا حقيقيًا إلى Graph API.
   - في لوحة Meta: عنوان الويب هوك `https://<ngrok-host>/api/v1/inbound/whatsapp`، اشترك في حقل `messages`، وضع نفس Verify Token.
   - في **الإعدادات → المستخدمون**: ضع رقم هاتفك على شكل `01xxxxxxxxx`. أرسل من واتساب: «محتاج 20 طن أسمنت» ⇒ يجب أن يصلك رد بكود طلب الشراء أو سؤال توضيح.
   - جرّب رقمًا غير مسجَّل: لا يصل أي رد، ويظهر `received_unmatched` في التدقيق. جرّب App Secret خاطئًا: `401` وسطر سجل يذكر السبب دون الأسرار.
4. **PDF عربي:** أنشئ أمر شراء بعد اعتماد بشري، افتح زر **PDF**، وتأكد من: القراءة من اليمين لليسار، اتصال الحروف، عدم انعكاس الأرقام، وعدم ظهور مربعات فارغة. إن ظهرت مربعات: `python -c "from app.services.pdf_fonts import arabic_ready; print(arabic_ready())"` يجب أن يطبع `True`.
5. **الإقلاع الآمن:** جرّب `APP_ENV=staging` مع `BOOTSTRAP_DEMO_PASSWORD=Demo!Pilot2026` — يجب أن ترفض الخدمة الإقلاع، و`python -m app.cli seed-demo` يجب أن ترفض التنفيذ.
6. **الفحوص السريعة:** `ruff check app tests`، `pytest tests -q`، `npm run typecheck && npm run lint && npm test && npm run build`، `python scripts/e2e_journeys.py`.

## 5. مخاطر الإطلاق المتبقية

1. **تحديد المستأجر يعتمد على إعداد صحيح لـ `phone_number_id`.** لا توجد قاعدة بيانات أرقام مركزية؛ إن نسيت حفظ الرقم على شاشة التكاملات فكل رسالة ستُسجَّل `unknown_recipient` ولن يصل رد. هذا ظاهر في السجل والتدقيق، لكنه يتطلب انتباه المشغّل.
2. **نافذة الـ 24 ساعة في Meta.** خارج النافذة لا يُسمح إلا برسائل قوالب معتمدة؛ الرد التلقائي على رسالة الموظف يقع داخل النافذة بطبيعته، لكن أي مبادرة خارجية تحتاج قالبًا.
3. **PDF العربي بلا تحقق بصري آلي.** التضمين والتشكيل والترتيب مُثبتة اختباريًا، لكن أول مستند يُرسل لمورّد يجب أن يراه إنسان (خطوة 4 أعلاه).
4. **المورّدون لم يُختبروا حقيقيًا.** أول مكالمة/رسالة حقيقية لكل مورّد قد تكشف فروقًا في الصيغ أو الأذونات؛ خطة العمل: تجربة واحدة بمراقبة بشرية لكل قناة قبل الاعتماد.
5. **حدود البيئة:** RLS و`pgvector` والبحث الثلاثي مُثبتة في CI على PostgreSQL فقط، والنسخ المتعددة مُثبتة عبر Redis محلي؛ لا يوجد بعد قياس حمل على أكثر من نسخة واحدة (محدِّد المعدل ما زال داخل العملية).
6. **واجهة المتصفح غير مُشغَّلة آليًا** في هذه البيئة؛ الاعتماد على فحص الأنواع والبناء واختبارات الوحدة ورحلات HTTP/WebSocket.
