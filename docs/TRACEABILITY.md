# Requirements traceability

Source of truth for behaviour is the SRS. This document maps each requirement area to the code
that implements it and the tests that prove it. It is generated by hand from the codebase and
kept honest: a row only says **Done** when an executable test exercises the behaviour.

Status vocabulary:

* **Done** — implemented and covered by an executable test.
* **Partial** — implemented, but one documented sub-case depends on an external system that is not
  available in this environment (real provider credentials, Postgres RLS, pgvector search).
* **Stub-with-adapter** — the interface and the deterministic fake exist; the real client is
  behind credentials and is not exercised here.

Test counts (513 backend tests, 27 frontend tests) and coverage (85% line coverage of
`backend/app`) are reproduced in `docs/PR_DESCRIPTION.md`.

## What is not covered here

1. Live PostgreSQL-only features (RLS enforcement, pgvector similarity ranking, `pg_trgm` search)
   are guarded by dialect checks and enabled in production, but the sandbox has no Postgres.
2. Real third-party clients (Anthropic/OpenAI, Twilio, Meta Cloud API, Paymob, ERP HTTP endpoints)
   are implemented but not exercised: tests use their deterministic fakes.
3. Browser-level E2E (Playwright) is not part of the committed suite; the UI is verified by a real
   production build, TypeScript strict typecheck, ESLint, and 27 component/interaction tests.
